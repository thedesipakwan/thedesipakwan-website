# The Desi Pakwan — handmade thekua & chakli, shipped across India

Direct-to-consumer storefront: Next.js 15 (App Router) + Tailwind v4 + GSAP + Razorpay + Resend.
No database — the Razorpay dashboard is the order list, and order notes carry everything needed
to pack and ship.

## Quick start

```bash
npm install
cp .env.example .env.local   # fill in your keys
node scripts/generate-placeholders.mjs   # only needed if /public/images is empty
npm run dev
```

## Environment variables (`.env.local`)

| Variable | What it is |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | Canonical site URL (no trailing slash) |
| `NEXT_PUBLIC_RAZORPAY_KEY_ID` | Razorpay key id (`rzp_test_…` first, `rzp_live_…` to go live) |
| `RAZORPAY_KEY_SECRET` | Razorpay key secret (server only) |
| `RAZORPAY_WEBHOOK_SECRET` | Secret you set when registering the webhook |
| `RESEND_API_KEY` | Resend API key for order emails |
| `OWNER_EMAIL` | Where "new order" emails go |
| `NEXT_PUBLIC_WHATSAPP` | Your WhatsApp number, digits only with country code, e.g. `919876543210` (used by every WhatsApp button and the order emails) |
| `FROM_EMAIL` | e.g. `The Desi Pakwan <info@thedesipakwan.com>` (domain must be verified in Resend) |
| `NEXT_PUBLIC_GA_ID` | Optional GA4 id |

Also update `data/site.ts`: Instagram, FSSAI licence number, jurisdiction city.

## How to add a product (under 5 steps)

1. Open `data/products.ts` and copy an existing product object.
2. Give it a unique `slug`, `name`, variants with unique `sku`s and integer prices.
3. Add two images to `public/images/products/`: `<slug>-1.jpg` (pack shot) and `<slug>-2.jpg`
   (texture close-up), square, shot on a pale pista `#F4F8EA` background.
4. (Optional) add `badges`, `featured: true`, `sweetness` (thekua) or `spice` (chakli).
5. `npm run build` — the shop grid, product page, sitemap and structured data update themselves.

## Replacing placeholder images

Every placeholder was generated by `scripts/generate-placeholders.mjs` with the exact filename
the site expects. Drop the real file over the placeholder (same name, same folder) — no code
changes. The script never overwrites existing files, so re-running it is always safe.

- `public/images/hero-thekua-stack.png` — transparent cut-out for the hero
- `public/images/products/<slug>-1.jpg` / `-2.jpg` — product shots
- `public/images/sequence/thekua-press-000.webp` … `-059.webp` — 60 frames of the press-and-fry
  turntable (export from video, square, ~480–800px)
- `public/images/og-image.jpg` — 1200×630 social preview
- `public/lottie/` — optional `wheat.json`, `jaggery.json`, `ghee-drop.json` (the ingredients
  section currently uses built-in SVG animations; swap in Lotties via `lottie-react` if desired)

## Payments (Razorpay, no database)

1. Client POSTs cart + address to `/api/razorpay/order`.
2. Server **recomputes the amount from `data/products.ts`** (client prices are never trusted),
   creates the Razorpay order, and stores items/address/consent in the order `notes`.
3. Razorpay Checkout opens; on success the client calls `/api/razorpay/verify` (HMAC check with
   `crypto.timingSafeEqual`) and routes to `/order/success`.
4. The `payment.captured` **webhook** (`/api/razorpay/webhook`) verifies `x-razorpay-signature`
   against the raw body, refetches the order notes, and sends both emails via Resend. Emails only
   fire from the webhook, so they arrive even if the buyer closes the tab.

### Test an order end-to-end

1. Use `rzp_test_…` keys in `.env.local`.
2. `npm run dev`, add to cart, checkout, pay with Razorpay's test UPI/cards.
3. For webhook emails locally, expose the port (`npx untun tunnel http://localhost:3000` or
   ngrok) and register `https://<tunnel>/api/razorpay/webhook` in the Razorpay dashboard →
   Webhooks, event `payment.captured`, with your `RAZORPAY_WEBHOOK_SECRET`.

## Going live

1. Razorpay: complete KYC (policies pages are live at `/policies/*` — Razorpay needs them),
   switch `.env` to live keys.
2. Register the production webhook: `https://<domain>/api/razorpay/webhook`, event
   `payment.captured`, same secret as `RAZORPAY_WEBHOOK_SECRET`.
3. Resend: verify the sending domain, set `FROM_EMAIL` accordingly.
4. Vercel: add the domain, set all env vars from `.env.example`, deploy.
5. Replace placeholder images (list above), the FSSAI number in `data/site.ts`, and the
   testimonials in `data/testimonials.ts`.
6. Razorpay dashboard → Settings → Payment capture: turn on **automatic capture**. Order
   emails are sent only for captured payments, so without this they wait for manual capture.

## Order safety — when is an order "real"?

**Only ship an order when the "New order" email arrives** (or the order shows as *Paid*
in the Razorpay dashboard). Nothing else counts:

- Clicking Pay, cancelling, failed and pending payments send **no** email.
- The email is sent only after the server re-checks the payment with Razorpay's API:
  captured, belongs to this order, full amount, in INR.
- The "Order placed" page is shown only after Razorpay confirms the order is paid, so a
  screenshot of a typed-in success URL is not proof of payment.
- Repeated Razorpay notifications for the same order never send a second email: each email
  carries an idempotency key tied to the order ID, so Resend delivers it once even if two
  notifications arrive at the same instant, and the order is also marked `emailed` in its
  notes for any later retries.
- While the site runs on `rzp_test_` keys, order emails say **TEST — DO NOT SHIP**, and
  customer emails are only sent to `OWNER_EMAIL` (so test keys can't be abused to email strangers).
- Each order records the unit price charged. If an order is paid at an old price, reuses a
  checkout started over 2 hours earlier, or its items don't add up to the amount paid, the
  owner email is marked **CHECK BEFORE SHIPPING** and the customer gets no confirmation —
  ship it or refund it from the Razorpay dashboard.
- If Razorpay or Resend is briefly unreachable, the webhook asks Razorpay to retry, so a paid
  order is never silently lost.
- Order creation and status checks are rate-limited per IP. For a hard global limit on
  Vercel, also add a WAF rate-limit rule for `/api/razorpay/*`.
- Run `node scripts/security-check.mjs` (with `npm run dev` running) to re-test all of this.

## Project map

- `data/` — products, site config, testimonials (the only files you edit day-to-day)
- `app/` — pages + the three Razorpay API routes
- `components/home/` — the animated homepage sections
- `components/motion/` — Lenis, page transition, cursor, magnetic buttons, scroll sequence
- `emails/` — React Email templates (owner + customer)
- `scripts/generate-placeholders.mjs` — regenerates any missing placeholder asset

## Conventions

- Brand palette only (paan/kesariya/pista/mehndi/sindoor/kesar — deep paan green, molten
  kesariya orange, pale pista, burnt-sindoor CTAs; food illustrations use the separate
  wheat/earth colours) — never purple, violet, indigo or blue, never pink, and never the
  generic brown/gold/cream snack-brand look.
- Every animation respects `prefers-reduced-motion`.
- Prices are integers in INR, GST-inclusive; shipping ₹49, free above ₹499 (`data/site.ts`).
